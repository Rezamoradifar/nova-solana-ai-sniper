# اتصال سرویس‌ها و تأیید راه‌اندازی

این نسخه اتصال داخلی ربات تلگرام به API در Docker را اصلاح می‌کند. در نصب PM2، مقدار پیش‌فرض localhost حفظ می‌شود. برای API روی میزبان دیگر، INTERNAL_API_URL را تنظیم کنید.

## پیش‌نیازهای واقعی

در فایل خصوصی .env روی سرور، DATABASE_URL، REDIS_URL، JWT_SECRET و ENCRYPTION_KEY معتبر لازم است. کلید رمزگذاری نصب موجود را تغییر ندهید؛ کیف پول‌های موجود به آن وابسته‌اند.

برای تلگرام TELEGRAM_BOT_TOKEN و شناسه مدیر TELEGRAM_ADMIN_IDS، برای اتصال اختصاصی سولانا HELIUS_API_KEY یا SOLANA_RPC_URL و SOLANA_WS_URL، و برای تحلیل OpenAI مقدار OPENAI_API_KEY را تنظیم کنید. این مقادیر را در گیت یا گفت‌وگو منتشر نکنید.

مسیر فعلی تحلیل، در صورت تنظیم OpenRouter آن را مقدم می‌داند؛ در مسیر تک‌مدلی Anthropic بر OpenAI اولویت دارد. برای انتخاب OpenAI در همین مسیر، کلیدهای OpenRouter و Anthropic نباید در محیط API تنظیم شده باشند. اتصال مستقیم به حساب یا گفت‌وگوی ChatGPT وجود ندارد.

## راه‌اندازی و بررسی

پس از اعمال تغییرات و تنظیم .env، در پوشه پروژه:

```bash
docker compose up -d --build
 docker compose ps
curl --fail --max-time 10 http://127.0.0.1:4000/health/ready
```

مسیر health/ready تنها وقتی پاسخ موفق می‌دهد که راه‌اندازی worker کامل شده، PostgreSQL و Redis پاسخ بدهند و درخواست RPC سولانا موفق باشد. این بررسی، صحت تمام صرافی‌ها، فعال‌بودن AI یا انجام معامله واقعی را تضمین نمی‌کند. برای خطاها، لاگ API و تلگرام را روی سرور بررسی کنید و پیش از اشتراک‌گذاری اطلاعات محرمانه را حذف کنید.

## مواردی که هنوز به تأیید عملی نیاز دارند

- پاسخ موفق تلگرام و اتصال مینی‌اپ به دامنه HTTPS واقعی.
- مشاهده رویدادهای جدید اسکنر و پاسخ واقعی سرویس هوش مصنوعی.
- مسیر معتبر خرید و فروش در Jupiter؛ اجرای مستقیم Orca و Meteora موجود نیست.
- Raydium مستقیم تا تأیید شبیه‌سازی خرید و فروش غیرفعال است.
- تنظیم LIVE_TRADING در این اصلاح تغییر نکرده است؛ نصب پیش‌فرض در حالت کاغذی باقی می‌ماند. کنترل معاملات واقعی در اختیار اپراتور است.

هیچ گزارش تست محلی جای بررسی سرور واقعی و تراکنش‌های ثبت‌شده را نمی‌گیرد.
