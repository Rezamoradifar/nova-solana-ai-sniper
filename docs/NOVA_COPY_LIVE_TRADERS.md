# فهرست زندهٔ تریدرها و مسیر تنظیم کپی

صفحهٔ `/copy-trading` کارت‌های تریدرهای فعال GMGN را با سود محقق‌شدهٔ دلاری، بازده، تعداد خرید/فروش، برچسب‌ها و زمان فعالیت نمایش می‌دهد. سود سبز، زیان قرمز و مقدار گزارش‌نشده `—` است. جستجو، مرتب‌سازی و بازه‌های ۷ و ۳۰روزه پشتیبانی می‌شوند. فهرست بین حداکثر ۲۰ کیف پول نمونهٔ فعال GMGN مرتب می‌شود؛ رتبه‌بندی کل بازار یا تأیید خودکار مناسب‌بودن یک تریدر برای کپی نیست.

## دادهٔ واقعی

- مسیر جدید: `GET /api/public/copy-trading/traders?period=7d` یا `30d`.
- نامزدها از فید رسمی Smart Money و عملکرد دوره از `POST /v1/user/wallet_profits` دریافت می‌شوند. این POST فقط خواندن تحلیل است؛ امضا، سفارش یا تراکنش زنجیره‌ای ارسال نمی‌کند.
- یک بررسی واقعی سازگاری نشان داد GET آمار چند کیف پول فقط اولین کیف پول را برمی‌گرداند؛ مسیر batch سود، هر دو کیف پول آزمایش را با هویت مستقل برگرداند. پیاده‌سازی از همین مسیر batch استفاده می‌کند.
- `realized_profit` سود محقق‌شدهٔ دوره و `realized_profit_cost` مبنای هزینهٔ همان دوره است. بازده از نسبت همین دو مقدار محاسبه می‌شود. فیلدهای `total_realized_profit` و `total_profit` مادام‌العمر جایگزین سود دوره نمی‌شوند. حجم معامله نیز سود معرفی نمی‌شود.
- نام و نرخ برد سه تریدر پیشرو از درخواست‌های اختیاری و محدود `wallet_stats` دریافت می‌شوند. شکست این درخواست‌ها، سود معتبر batch را مخفی نمی‌کند. نرخ برد گزارش‌نشده حدس زده نمی‌شود.
- پاسخ‌ها با آدرس کیف پول تطبیق داده می‌شوند؛ آدرس نامرتبط، تکراری یا متناقض پذیرفته نمی‌شود. سود نمونهٔ ثبت‌شدهٔ GSP به SOL جدا از سود دلاری کیف پول در GMGN است.
- نتیجهٔ موفق ۶۰ ثانیه نگه‌داری و درخواست‌های هم‌زمان کاربران ادغام می‌شوند. خطا باعث ۶۰ ثانیه فاصلهٔ تلاش بعدی می‌شود. زمان مشاهدهٔ دادهٔ قبلی با درخواست ناموفق تازه نمی‌شود.
- نشان LIVE DATA به دادهٔ عملکرد تازه وابسته است؛ دادهٔ قدیمی‌تر از ۹۰ ثانیه، پاسخ نامعتبر و خطای دریافت، نشان لایو نمی‌گیرند. آمادگی موتور کپی جداگانه نمایش داده می‌شود.
- کلید موجود `GMGN_API_KEY` سرور استفاده می‌شود و در پاسخ API، URL مرورگر یا گزارش خطا منتشر نمی‌شود. کلید نمونهٔ عمومی فقط در بررسی توسعه استفاده شد و در تنظیم برنامه قرار نمی‌گیرد.

## اتصال و تنظیم کپی

انتخاب تریدر، آدرسش را در URL صفحه حفظ می‌کند. اتصال کیف پول مرورگر، ورود حساب و بازگشت از مدیریت کیف پول معاملات، انتخاب را از بین نمی‌برند. اتصال مرورگر فقط آدرس را به اشتراک می‌گذارد؛ موتور خودکار موجود از کیف پول فعال معاملات حساب استفاده می‌کند.

کاربر سقف SOL، درصد کپی و تریدر را بررسی و صریحاً تأیید می‌کند. اگر موتور آماده نباشد، تنظیم از مسیر جدید `POST /copy-trades/drafts` با `isActive: false` ذخیره می‌شود. تغییر حساب، کیف پول معاملات، تریدر، سقف‌ها یا وضعیت اجرای موتور، تأیید قبلی را نامعتبر می‌کند. تأیید ذخیرهٔ متوقف، اجازهٔ خرید واقعی در وضعیت LIVE نمی‌شود. چنین تنظیمی با آماده‌شدن موتور خودبه‌خود فعال نمی‌شود؛ کاربر باید فعال‌سازی را انتخاب کند. مسیر قدیمی `POST /copy-trades` رفتار قبلیِ ایجاد تنظیم فعال را دارد. مسیر draft همیشه متوقف ایجاد می‌کند؛ API قدیمی این مسیر را ندارد و به‌جای نادیده‌گرفتن یک فیلد JSON و ایجاد تنظیم فعال، درخواست را رد می‌کند. سقف خرید سرور، کنترل حساب فعال، رد کیف پول داخلی و توقف‌های موتور حفظ شده‌اند.

حساب بدون کیف پول معاملات به مدیریت کیف پول هدایت می‌شود و لینک بازگشت، تریدر انتخابی را حفظ می‌کند. هیچ کیف پول معاملات، سرمایه، کلید یا مرجع کپی خودکار برای کاربر ساخته یا انتخاب نمی‌شود.

## نصب

این نسخه روی شاخهٔ `codex/nova-copy-live-traders-20261025`، بر پایهٔ نسخهٔ Mainnet و طراحی لوکس PR #23 قرار دارد. نصب با `deploy-nova-mainnet-luxury.py` و SHA کامل همین نسخه، وب و API را همراه بکاپ و بازیابی ارتقا می‌دهد. برای نمایش فید GMGN، RPC اختصاصی تازه لازم نیست؛ کلید GMGN موجود سرور کافی است، به شرط مجوز و دسترس‌پذیری provider.

تا پیش از تهیه و تأیید HTTP/WSS شبکهٔ اصلی، دستور نصب بدون `--activate-copy` و `--repair-rpc` اجرا می‌شود. نصب رابط و فید به معنی فعال‌شدن موتور معاملات نیست. مینی‌اپ تلگرام غیرفعال می‌ماند. migration یا تغییر schema وجود ندارد.

### توقف در نگه‌داری تصویر قبلی

خطای `Retain old api image failed` مربوط به پیش از ساخت یا جایگزینی سرویس‌هاست. نسخهٔ قبلی متن خطای Docker را پنهان و دستور Restore را زودتر از ایجاد manifest چاپ می‌کرد؛ پوشهٔ همان تلاش الزاماً بکاپ قابل‌بازیابی نیست. صرف این خطا دلیل اجرای Restore نیست.

نصب‌کنندهٔ اصلاح‌شده شناسهٔ کامل تصویر فعلی را ثبت می‌کند و نگه‌داری را با ID محلی و در صورت نیاز ارجاع اولیهٔ همان کانتینر امتحان می‌کند. ارجاع فقط وقتی پذیرفته می‌شود که ID کامل آن دقیقاً با تصویر فعلی برابر باشد. پس از tag و دوباره پس از build، هم تصویر بکاپ و هم ID لازم برای rollback بررسی می‌شوند؛ tag جابه‌جاشده، تصویر حذف‌شده یا نبود امکان بازیابی موجب توقف پیش از جایگزینی می‌شوند. pull کردن tag متغیر، commit کردن کانتینر، حذف تصویر، prune یا ردکردن بکاپ مسیر جایگزین نیستند.

خطاهای این مرحله به شکل `NOVA_IMAGE_CHECK=<service>:<step>:<code>` چاپ می‌شوند؛ از جمله `NO_SUCH_IMAGE`، `DISK_FULL`، `PERMISSION_DENIED` و `DAEMON_UNAVAILABLE`. جزئیات اصلی فقط در `image-retention.private.jsonl` داخل پوشهٔ خصوصی همان تلاش، با دسترسی ۶۰۰ نگه‌داری می‌شوند. محتوای این فایل برای چت عمومی نیست. علت خطای قبلی از متن پنهان‌شده قابل تشخیص قطعی نیست.

فقط بعد از آماده‌شدن فایل‌های بازیابی و بررسی تصاویر، `NOVA_MAINNET_ROLLBACK_READY=YES` و دستور Restore چاپ می‌شوند. شکست مرحلهٔ آماده‌سازی `NOVA_MAINNET_REPLACEMENT_STARTED=NO` می‌دهد. تلاش دوباره با SHA اصلاح‌شده به پاک‌سازی checkout، تغییر `.env` یا حذف بکاپ قبلی نیاز ندارد.

## شواهد

در بررسی فقط‌خواندنی سرور، release وب `99c05535c0227ee4496d18788ca801c7b63de001` بود؛ GMGN متصل، موتور کپی متوقف، حالت PAPER و اسکنر ناسالم گزارش شدند. API موجود سایت، آمار واقعی یک کیف پول را برگرداند. این مشاهده و بررسی batch رسمی، اجرای معامله یا نصب این نسخه روی VPS را اثبات نمی‌کنند.

تست‌ها هویت و واحد سود، تفاوت دوره/کل تاریخ، علامت سود و زیان، cache و خطا، حفظ انتخاب در ورود، اتصال کیف پول، ذخیرهٔ متوقف، بازگشت مدیریت کیف پول، رضایت صریح برای فعال‌سازی، دادهٔ قدیمی، موبایل و رگرسیون‌های قبلی را پوشش می‌دهند. دادهٔ تصویرهای آزمون مرورگر کنترل‌شده است.
